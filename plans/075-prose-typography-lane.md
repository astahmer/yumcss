# Feature Plan: Prose stylesheet lane

**Status:** Implemented — §8 was answered as `go ahead`, and §7 settled on the
recommended option in every case (D1 `pandwind/prose/tailwindcss`, D2 full
parity, D3 keep the guard rewrite, D4 decline the element variants, D5 decline a
second family). §9 records what shipped.
**Created:** 2026-09-17
**Owner:** Pandwind maintainers

## 1. Summary and context

The ask was: _"maybe we should also have some prose/typography preset? based
on w/e tailwind has i guess"_.

Every Tailwind project that renders markdown gets its typographic scale from
`@tailwindcss/typography@0.5.20`: one `.prose` class on a container, a
descendant tree that styles the plain HTML inside it, a `--tw-prose-*`
variable layer for theming, an `.prose-invert` dark-mode switch, four size
modifiers, 22 color-theme modifiers, and an `.not-prose` escape hatch. A
project that moves its style objects to Pandwind loses all of it, which is the
same loss that `plans/074-ecosystem-presets-and-resets.md` answered for
Preflight with `pandwind/reset/<ecosystem>`.

The word in the ask is _preset_, but a preset is the wrong lane here, and the
mismatch is structural rather than a matter of taste:

- `CssPreset` (`packages/pandwind/src/types/typings.ts:305`) carries
  `conditions`, `properties`, `strict`, `colorPalettes`, and
  `cssVariables`. A preset names CSS properties and the token groups each
  property resolves against; it cannot declare a rule for an element other
  than the one carrying the class. The core port is 274 descendant rules, each
  of the shape
  `:where(h1):not(:where([class~="not-prose"], [class~="not-prose"] *))`.
- `cssVariables` (`typings.ts:326`) is interop data. The stylesheet compiler
  publishes a preset's token custom properties and never declares the interop
  block, so a "prose preset" holding `--tw-prose-*` values renders nothing
  until something else emits the rules that read them.
- Element conditions can already express a descendant tree — `_peerFocus` is
  `.peer:is(:focus, [data-focus]) ~ &`, so a project can add `_p: "& p"` —
  but that swaps one class for roughly twenty condition names every caller has
  to type, and it emits `.cls p` with class specificity where Tailwind emits
  zero-specificity `:where(p)`. That is a worse contract than either lane
  below.

The shape that fits is the one 074 established for baselines: a plain CSS
asset, like the resets. It adds no JavaScript, no type, and no
`createCss` behavior, and it is opt-in at the import.

## 2. Goals

- Ship the Tailwind typography family as `pandwind/prose/tailwindcss`, a
  CSS asset ported from `@tailwindcss/typography@0.5.20` through the pinned
  `tailwindcss@4.3.3` compiler, with a provenance header that names upstream,
  its license, and every deliberate divergence.
- Keep the upstream class and custom-property names (`.prose`,
  `.prose-sm`/`-lg`/`-xl`/`-2xl`, `.prose-invert`, `.not-prose`,
  `--tw-prose-*`, `--tw-prose-invert-*`) so a project's existing overrides
  and its `prose`/`prose-invert` markup keep working.
- Generate the asset from the pinned package, so a version bump is a
  `prose:generate` run plus a reviewed diff rather than a hand edit, and
  `prose:check` fails on drift.
- Keep the addition off every existing path: no byte in `pandwind/css`,
  `pandwind/tw`, or any runtime lane changes, and the new subpath appears as
  its own measured row.
- Document the lane and its cascade position the way `api/resets.md` does,
  including the `reset` / `preset` / `prose` distinction.

## 3. Non-goals

- Do not ship a prose _preset_ or any new typed vocabulary. The feature is a
  stylesheet, and §1 records why the preset lane cannot hold it.
- Do not ship Tailwind's `prose-*` element variants
  (`prose-headings:`, `prose-a:`, `prose-img:`, … — the plugin's
  `addVariant` family, 34 names). Variants need a utility engine to attach a
  utility to; a static asset cannot carry them. Element-level restyling stays
  in the authored CSS lane, and a preset-side element-condition family is a
  separate decision if it is ever wanted (§7 D4).
- Do not re-implement prose as Pandwind style objects, atomize it, or fold it
  into the generated stylesheet. A project that wants prose rules generated by
  its own preset is asking for a different feature.
- Do not port a second prose family (UnoCSS `preset-typography`, Panda
  recipes, StyleX) before the Tailwind port has a consumer.
- Do not vendor without provenance, an upstream permalink, or a license
  notice, and do not keep a fallback copy of the upstream data in the
  repository.

## 4. Proposed design

### 4.1 Subpath and family

`pandwind/prose/<ecosystem>`, first and for now only
`pandwind/prose/tailwindcss`. It is a sibling of `pandwind/reset/<ecosystem>`
in packaging (a `.css` file copied into `dist/`) and a sibling of it in
purpose (an engine's stylesheet preserved for a project that left that engine),
not a third member of the `preset`/`reset` pair. The family name also avoids
the one-letter collision the maintainer already flagged between `preset` and
`reset`.

A prose stylesheet is deliberately _not_ a reset: a reset flattens browser
defaults everywhere, before authored CSS, and declares no type; a prose
stylesheet is opt-in per subtree, applied by a class the author writes, and is
entirely typographic. Both ship as CSS, neither is a preset.

### 4.2 Generation

`scripts/promote-tailwind-prose.ts`, mirroring
`scripts/promote-tailwind-preset.ts` (`requireFromPandwind.resolve` for the
pinned packages, a `--check` mode that compares checked-in bytes against a
fresh render). It:

1. adds `@tailwindcss/typography` as a pinned devDependency of
   `packages/pandwind` (its peer range accepts `tailwindcss >=4`, and the
   pinned `tailwindcss@4.3.3` / `@tailwindcss/node@4.3.3` already compile it);
2. compiles `@import "tailwindcss"; @plugin "<resolved typography>";` with a
   candidate list — the candidate list _is_ the scope decision, because
   Tailwind only emits the modifiers it is asked for;
3. slices the document from `@layer utilities` to the end. For a candidate
   list that contains only `prose*` candidates that slice is the prose family
   alone, and it is self-contained: `.prose` declares the 18 light and 18
   invert defaults itself, so dropping the `@layer theme` / `@layer base`
   prefix loses nothing;
4. rewrites the guard form `[class~="not-prose"], [class~="not-prose"] *` to
   `.not-prose, .not-prose *` (identical matching, ~5.5 KB smaller raw:
   inside `:where()` both contribute zero specificity), and wraps the block in
   `@layer prose`;
5. prepends the provenance header: upstream package and version, permalink,
   MIT notice, and the divergence list.

`package.json` gains `prose:generate` / `prose:check` beside
`presets:generate` / `presets:check`, and `pnpm run check` chains
`prose:check`.

### 4.3 Cascade position

The asset's rules sit in `@layer prose`.

- On the default `specificity` cascade nothing has to be declared: Pandwind
  emits unlayered rules, unlayered beats layered, so an atomic class always
  wins over a prose declaration for the same element.
- On `cascade: "layers"` the project declares
  `@layer reset, prose, pandwind;`. Layer order is fixed by first appearance,
  so the order must include `prose` ahead of `pandwind` or atoms lose to
  prose.
- This mirrors Tailwind's own output, where the `.prose` rules are emitted at
  the top of `@layer utilities` and the utility classes follow them.

### 4.4 Variable contract

The 18 `--tw-prose-*` names and their 18 `--tw-prose-invert-*` twins are
kept verbatim (`body`, `headings`, `lead`, `links`, `bold`,
`counters`, `bullets`, `quotes`, `quote-borders`, `captions`,
`kbd`, `kbd-shadows`, `code`, `pre-code`, `pre-bg`, `hr`,
`th-borders`, `td-borders`). A project that already overrides them on
Tailwind keeps its overrides, the port stays diffable against upstream, and the
documented customization path is the same one Tailwind documents.

Divergences to record in the header, all mechanical from the port:

1. the rules are wrapped in `@layer prose` instead of Tailwind's
   `@layer utilities`, so the layer order is the project's declaration
   (`@layer reset, prose, pandwind`);
2. the `.not-prose` guard uses a class selector instead of the attribute form;
3. the `prose-*` element variants are absent (they are utilities in Tailwind);
4. the color-theme modifiers are a scope decision, not an oversight — see §7 D2.

### 4.5 Measured cost

Compiled with the pinned `tailwindcss@4.3.3` + `@tailwindcss/typography@0.5.20`
through `@tailwindcss/node` (the same mechanism `presets:generate` uses),
gzip level 6 like the rest of `size.md`. Figures are the `@layer utilities`
slice, which is the asset itself, not the surrounding Tailwind document.

| scope                                    |      raw |    gzip | guard chains |
| ---------------------------------------- | -------: | ------: | -----------: |
| `.prose` alone                           | 15.35 KB | 1.83 KB |           86 |
| `.prose` + `.prose-invert`               | 16.35 KB | 1.97 KB |           86 |
| core: `prose` + 4 sizes + `prose-invert` | 44.99 KB | 3.37 KB |          274 |
| core, guard compacted                    | 39.64 KB | 3.28 KB |          274 |
| full: core + 22 color themes             | 56.18 KB | 4.92 KB |          274 |
| full, guard compacted                    | 50.83 KB | 4.53 KB |          274 |

The shipped file is that last row plus the provenance header, so the row
`reference/size.md` lists is the whole asset: **54.24 KB raw / 6.31 KB gzip**.

For scale, the three shipped resets are 10.99 KB / 4.11 KB
(`tailwindcss`), 6.31 KB / 2.79 KB (`panda`), and 3.38 KB / 1.75 KB
(`pandwind`). The prose asset is larger than any of them because it is a
component stylesheet rather than a baseline, and because a static asset must
carry every modifier a Tailwind project could have used, where Tailwind's
compiler ships only the candidates a build actually referenced. The size is
opt-in: a project that imports no prose pays nothing, and one that imports it
pays the row it chose.

### 4.6 Packaging, wiring, and evidence

- `packages/pandwind/package.json`: `"./prose/tailwindcss"` →
  `{ pandwind: "./src/prose/tailwindcss.css", default: "./dist/prose/tailwindcss.css" }`,
  the same dual-target shape the reset subpaths use.
- `packages/pandwind/tsdown.config.ts`: extend the existing `copy` entry so
  `src/prose/*.css` lands in `dist/prose`.
- `knip.json`: `src/prose/*.css` as a production entry beside
  `src/reset/*.css`; `postcss-selector-parser` already carries the
  suppression note for this kind of subpath.
- `scripts/check-package-surface.ts`: the new subpath is part of the declared
  surface, so `surface:check` must list it.
- tests: `tests/package-exports.test.ts` asserts the subpath target and that
  the checked-in file starts with its provenance header;
  `tests/packed-consumer.test.ts` resolves `pandwind/prose/tailwindcss` from
  the packed tarball the way it resolves `pandwind/reset/tailwindcss`.
- docs: `docs/src/content/docs/api/prose.md`, with the layer-order note, the
  variable table, the divergence list, and a `Reset / preset / prose` table;
  `api/resets.md` gains a pointer so the three names are compared in one
  place.
- evidence: a `prose` row in the reset-stylesheet table of
  `docs/src/content/docs/reference/size.md`, plus the release tarball size
  check that already covers the resets.

## 5. Risks and mitigations

- **Silent parity gaps.** A project that used a Tailwind feature the port drops
  sees different typography rather than an error. Mitigation: the divergence
  list is part of the asset header and the docs page, and the scope decision
  (§7 D2) defaults to full parity so the only real gaps are the variants.
- **A static dump overshoots a JIT build.** Tailwind ships only the candidates
  a build referenced; the asset ships the whole chosen scope. Mitigation: the
  import is opt-in and per-scope, and the measured rows in §4.5 let a project
  pick the smallest one it needs.
- **Upstream drift.** `@tailwindcss/typography@0.5.x` is a v3-era plugin that
  still compiles under v4; it can change shape or stop compiling under a future
  Tailwind. Mitigation: pinned devDependency, generator-owned rewrite,
  `prose:check` in `pnpm run check`, and a hard failure rather than a silent
  skip when the compile yields nothing.
- **API-freeze policy.** `AGENTS.md` freezes the user-facing API. This adds a
  CSS asset subpath and no runtime, type, or `createCss` surface, so it is
  inside the "genuinely worthwhile additions" bar rather than the "new API"
  one — but it is still new published surface, which is why this note exists.
- **Cascade mistakes.** A project on `cascade: "layers"` that declares
  `@layer reset, pandwind` will see prose beat its atoms. Mitigation: the
  layer-order line is the first thing the docs page shows, and the header
  repeats it, exactly as the reset headers do.

## 6. Acceptance criteria

1. `pandwind/prose/tailwindcss` resolves from the packed tarball and renders
   the Tailwind typography scale on plain HTML (browser-checked evidence, not
   snapshot inspection).
2. `pnpm run prose:check` fails when the asset drifts from a fresh render, and
   passes on the checked-in bytes.
3. `surface:check`, `generated:check`, `generated:budget`, `knip`, and
   `package-exports` all pass with the new subpath declared.
4. `runtime-size.test.ts` budgets and every existing measured lane are
   unchanged: the asset ships no JavaScript and no type.
5. The header names upstream package, version, permalink, license, and every
   divergence, and the docs page documents the layer order, the variables, and
   the `reset` / `preset` / `prose` distinction.

## 7. Open decisions

Answered as the recommended option in each case; the notes below are kept as the
rationale for what shipped.

- **D1 — family and subpath name.** `pandwind/prose/tailwindcss` (recommended:
  short, no one-letter neighbour, states what the asset is) versus
  `pandwind/typography/tailwindcss` (matches the upstream plugin name, longer
  to type) versus `pandwind/reset/prose` (rejected: it is not a baseline).
- **D2 — scope.** Full parity, i.e. core plus the 22 color-theme modifiers
  (50.83 KB / 4.53 KB with the compacted guard), versus core only, i.e.
  `.prose` + `.prose-sm`/`-lg`/`-xl`/`-2xl` + `.prose-invert`
  (39.64 KB / 3.28 KB). Full parity is recommended: a project
  migrating from `prose-slate prose-invert` would otherwise get a silently
  different palette, and the themes cost 11 KB raw / 1.25 KB gzip on an
  already opt-in asset. Core-only is the leaner call if the project's own
  preset is considered the only correct source of prose colors, in which case
  the docs page must show the five-line `--tw-prose-*` override instead.
- **D3 — guard rewrite.** Keep the mechanical `.not-prose` rewrite
  (recommended) or stay verbatim so the asset diffs against upstream character
  for character. It is ~5.5 KB raw / 0.4 KB gzip.
- **D4 — element variants.** Decline for now (recommended, §3) or add a preset
  extension with element conditions (`_p: "& p"`, …) so
  `prose-a:text-blue-500` has a Pandwind equivalent. That is a new typed
  vocabulary and a separate note if it is ever wanted.
- **D5 — second prose family.** Decline until the Tailwind port has a consumer
  (recommended), or port UnoCSS's `preset-typography` (already in the
  lockfile as a transitive dependency) with `--un-prose-*` names.

## 8. Approval gate

`AGENTS.md` requires a written design note and an explicit maintainer
go-ahead before new user-facing surface. This note is the design half; the
implementation starts after the decisions in §7 are answered.
