# Codemod canonicality audit

Date: 2026-09-29 UTC
Scope: all source/target pairs exposed by the current built-in migration registry.

## Result

- 32 built-in adapters expose 1,024 registry pairs (32 × 32); 992 of 992 cross-adapter pairs have generated route fixtures, and the remaining 32 are identity no-ops.
- The refreshed primary capture has 32 Canonical, 260 Safe residual, and 732 Unverified pairs. It has 0 Valid but noncanonical and 0 Incorrect or lossy verdicts.
- The primary capture reports 473 typed residuals across 356 pairs. 352 residuals have unique exact-text spans and 121 have spans recovered from unique migration outcomes; 0 are unlocated or ambiguous.
- Residual dispositions are 93 configuration-dependent, 91 target/framework-incompatible, 289 unverified. These are classifications, not maturity promotions.
- Current route maturity is 22 experimental, 1,002 research. This audit promotes no route.

## Method and evidence limits

- Enumerated the live adapter registry and `migrationRouteProofCatalog`; it returns every built-in pair, including self-pairs.
- Refreshed every primary route with `runAdapterMigration` in safe mode and its route fixture’s file and source semantic. The capture intentionally has no project configuration and an empty read-only project index; configured and missing-config variants stay linked to route and catalog tests.
- Resolved exact installed versions from workspace/benchmark package trees. Missing targets are explicitly marked not installed.
- Compared output with registered official API guidance. Most official pages are rolling docs, not version-pinned pages; where docs do not identify a version, the installed package lock is the version evidence and exact-version target compilation remains unproven.
- Kept source/IR validation separate from target CSS syntax, target API shape, build, installed-project, SSR, and browser proof. A snapshot’s `valid: true` does not prove target output correctness.
- Kept all route maturity values copied from the route-proof catalog; the refresh updates outputs, artifacts, validations, residual causes and dispositions, source locations, and canonicality evidence only.

Chromium CSS grammar checks confirmed `CSS.supports("color", "red.300") === false`. Mantine’s 9.6 style-prop docs say `mx="auto"` maps to CSS `auto`, numeric dimensions convert from px into `rem` scaled by `--mantine-scale`, and palette colors are exposed through `--mantine-color-<name>-<shade>` variables.

## Reviewed findings

### A1 — unresolved Panda token references

Before the fix, 28 primary route outputs emitted the unresolved `red.300` and `blue.300` references as ordinary target values with no residual. Plain CSS does not accept `red.300` as a color, and token-aware targets need verified value matches rather than matching spellings. The Panda adapter now preserves source and reports typed `Configuration` residuals whenever those dotted references lack verified project metadata. The affected primary examples are now classified `safe residual`; route maturity remains unchanged.

Evidence: [source-preserving issue fixture](../../packages/codemod/tests/codemod-canonicality-audit.test.ts), [Panda → Linaria](../../packages/codemod/tests/routes/panda-to-linaria.test.ts), [Panda → Tailwind](../../packages/codemod/tests/routes/panda-to-tailwind.test.ts), [Panda → UnoCSS](../../packages/codemod/tests/routes/panda-to-unocss.test.ts), [Panda token usage](https://panda-css.com/docs/theming/usage), and [CSS color grammar](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value).

### A2 — Mantine style props lose source semantics

Before the fix, the primary fixture `<Box c="blue.6" mx="auto" maw={400} />` emitted `blue.6`, a fabricated `var(--mantine-spacing-auto)`, and unitless `400`. The adapter now maps `mx`/`my` and `px`/`py` to logical CSS properties, preserves `auto` as a keyword, converts numeric dimensions with Mantine's scaled-rem formula, and preserves unresolved theme paths with a typed `Configuration` residual. All 25 previously incorrect primary outputs now preserve the source; routes without target-project proof remain at their existing maturity.

The configured Mantine → UnoCSS route also exposed a host rewrite running after CSS validation had already rejected the emission. Host/component rewrites now run only after validation succeeds, so a failed projection keeps the original JSX and carries the typed residual.

Evidence: [Mantine issue fixtures](../../packages/codemod/tests/codemod-canonicality-audit.test.ts), [Mantine → Linaria](../../packages/codemod/tests/routes/mantine-to-linaria.test.ts), [Mantine → UnoCSS round trip](../../packages/codemod/tests/roundtrips/mantine-to-unocss-to-mantine.test.ts), Mantine [style props](https://mantine.dev/styles/style-props/), [color references](https://mantine.dev/theming/colors/), and [px/rem conversion](https://mantine.dev/styles/rem/). Installed target Linaria is 8.2.0; its `css` tag contains CSS declarations ([Linaria basics](https://github.com/callstack/linaria/blob/master/docs/BASICS.md)).

### A3 — target token names override mismatched source values

The pre-fix shared target policy looked up a target token by source reference before checking its resolved value. It now recovers a target reference only on an exact, unique, property-aware value match; otherwise it retains the resolved source value. A direct configured-catalog fixture covers the same-name/different-value case, which is not represented in the 1,024 primary route inputs.

Evidence: `TokenCatalog.preserveProgram` in [tokens.ts](../../packages/codemod/src/swap/tokens.ts) and the same-name/different-value case in [official-token-catalog.test.ts](../../packages/codemod/tests/official-token-catalog.test.ts).

### A4 — Mantine JSX hosts are not preserved through every target carrier

The original Mantine `<Box>` outputs used invalid target/component combinations. A literal-color fixture now isolates host projection from missing theme metadata: Mantine → Emotion keeps the renderable `Box` and applies `css(...)` through `className`; Mantine → Chakra and MUI preserve the foreign Mantine `Box` with typed host-framework residuals instead of attaching target-only props. MUI remains uninstalled, so its package behavior and route proof stay unverified.

Evidence: the [A4 issue fixture](../../packages/codemod/tests/codemod-canonicality-audit.test.ts), exact primary outputs in the route ledger, [Emotion CSS usage](https://emotion.sh/docs/%40emotion/css), [Chakra Box and `css`](https://chakra-ui.com/docs/components/box), and [MUI Box API](https://mui.com/material-ui/api/box/). Exact installed packages: Emotion 11.13.5 and Chakra 3.37.0; MUI unavailable.

### Review outcome

Reviewed 2026-09-27 before any adapter or expected-output edit. Findings A1–A4 were approved and fixed with source-specific fixtures, ordinary assertions, and described JJ revisions. Route proof then exposed and fixed the validation/host-rewrite ordering defect recorded under A2. The full route and round-trip matrix now passes. Snapshot refresh alone was not used as correctness evidence.

## Limits

The ledger captures one primary input per pair; linked generated route tests contain the additional scenarios. It does not compile every route as an independent target project. The 32 canonical entries are identity no-ops. Safe-residual entries prove that their primary input is preserved with typed residual evidence; their route-proof maturity remains separate. Routes without that exact evidence or target-project proof remain unverified. Existing installed-project route evidence remains governed by the proof catalog.
