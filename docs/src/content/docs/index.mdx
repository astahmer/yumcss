Pandwind is for teams who want typed style objects without throwing away
Tailwind, CSS, or the design-system conventions they already have. Start with
one lane; add the others only when they solve a real problem.

## Choose your starting point

### I already use Tailwind

Use [`tw()`](/api/tw/) to replace fragile class strings with an object whose
keys and values come from your actual Tailwind project.

```tsx
import { tw } from "./tw";

export const Card = () => (
	<article
		className={tw({
			flex: "col",
			gap: "4",
			rounded: "xl",
			bg: "white",
			p: "6",
			hover: { shadow: "lg" },
		})}
	>
		Your content
	</article>
);
```

### I want CSS objects

Use [`css()`](/api/css/) to author atomic styles without making Tailwind the
stylesheet engine. Create it from a preset so tokens and allowed values are
part of the type contract.

```ts
import { createCss } from "pandwind/css";
import { preset } from "./preset";

const css = createCss(preset);
const card = css.class({ backgroundColor: "$surface", padding: "4" });
```

### I am building a design system

Use [`createDesignCss()`](/api/design-css/) when component styles should read
like design intent: `$frame`, `$layout`, `$text`, semantic tokens, and explicit
states.

```ts
import { createDesignCss } from "pandwind/design";
import { preset } from "./preset";

const dcss = createDesignCss(preset);

const button = dcss.class({
	$frame: { fill: "$brand", pad: "4", corners: "md" },
	$text: { color: "$onBrand", weight: "semibold" },
});
```

### I am moving from another library

Start with the [migration guide](/guides/migrations/). Preview a diff, read the
residuals, and validate the target before changing the source tree.

## What Pandwind does for you

- **Types come from your project.** Tailwind utilities, preset tokens, and
  conditions are not copied into a second hand-maintained list.
- **Known work moves to build time.** Literal calls can become ordinary class
  strings or extracted atomic CSS.
- **Runtime values stay honest.** Dynamic colors, globals, fonts, and framework
  behavior use explicit escape hatches instead of pretending to be static.
- **You can inspect the result.** The playground, analyzer, inspector, and
  Studio show what was generated and what still needs attention.
