YumCSS is for teams who want typed style objects without throwing away CSS,
their design-system conventions, or an existing Tailwind workflow. For new
YumCSS code, start with `createCss`; add the other lanes only when they solve
a real problem.

## Primary path: css()

### Typed CSS objects for new code

Use [`css()`](/api/css/) as the default YumCSS API. It authors ordinary CSS
properties as typed objects and extracts static calls into atomic CSS without
making Tailwind the stylesheet engine.

```ts
import { createCss } from "yumcss/css";
import { defaultPreset } from "yumcss/preset/default";

const css = createCss(defaultPreset);
const card = css.class({ display: "flex", flexDirection: "column", gap: "4", padding: "6" });
```

## Other workflows when a project calls for them

If your project needs another styling workflow, add it alongside the primary
path instead of learning every API up front.

### I need a named design vocabulary

Use [`createDesignCss()`](/api/design-css/) when component styles should read
like design intent: `$frame`, `$layout`, `$text`, semantic tokens, and explicit
states.

```ts
import { createDesignCss } from "yumcss/design";
import { preset } from "./preset";

const dss = createDesignCss(preset);

const button = dss.class({
	$frame: { fill: "$brand", pad: "4", corners: "md" },
	$text: { color: "$onBrand", weight: "semibold" },
});
```

### I already use Tailwind

Use [`tw()`](/api/tw/) to replace fragile class strings with an object whose
keys and values come from your actual Tailwind project. This is the Tailwind
compatibility lane: Tailwind remains the stylesheet engine, while YumCSS
provides generated types, conflict handling, and build-time folding.

```tsx
import { tw } from "./tw";

export const Card = () => (
	<article
		className={tw({
			flex: "col",
			gap: "4",
			rounded: "xl",
			bg: "white",
			p: "6",
			hover: { shadow: "lg" },
		})}
	>
		Your content
	</article>
);
```

If you want Tailwind class output while keeping the `css()` property API, use
the [`ClassNameStrategy` adapter](/interop/tailwind-adapter/) instead.

### I need to combine existing classes

Use [`cx()`](/api/cx/) when a component receives YumCSS classes alongside
ordinary classes or styles from another library. It is a composition helper,
not a separate authoring path.

### I am evaluating a migration

Start with the [migration guide](/guides/migrations/). Preview a diff, read the
residuals, and check the route's canonicality and project-proof tier before
changing the source tree. The [API matrix](/interop/official-api-matrix/)
separates audited output from project-level proof.

## What YumCSS does for you

- **Types come from your project.** Tailwind utilities, preset tokens, and
  conditions are not copied into a second hand-maintained list.
- **Known work moves to build time.** Literal calls can become ordinary class
  strings or extracted atomic CSS.
- **Runtime values stay honest.** Dynamic colors, globals, fonts, and framework
  behavior use explicit escape hatches instead of pretending to be static.
- **Supporting tools explain and check the result.** The Playground helps you
  explore styles, the Inspector and Analyzer report on a project, and Migration
  Preview shows route output and residuals before files are edited.
