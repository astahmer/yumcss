## Why teams pick YumCSS

<CardGrid>
	<Card title="Tokens are types" icon="approve-check">
		`color: "#2563eb"` is a type error when your preset says colors are tokens. Typos, off-palette
		values, and unknown breakpoints never reach review.
	</Card>
	<Card title="Zero runtime for static styles" icon="rocket">
		Literal calls compile to strings. Variants from unions and ternaries are generated ahead of
		time. Truly dynamic values use inline CSS variables.
	</Card>
	<Card title="One atomic stylesheet" icon="document">
		Each declaration becomes one shared rule, so CSS grows with your design system, not with your
		component count. Split it per route if you need to.
	</Card>
	<Card title="Pick your output" icon="random">
		The same `css()` call can emit YumCSS atoms, Tailwind utilities, StyleX or Panda class names.
		Change strategy without touching components.
	</Card>
</CardGrid>
