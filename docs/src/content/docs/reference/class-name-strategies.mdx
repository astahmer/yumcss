A `ClassNameStrategy` decides which class name each declaration gets. The
style objects, types, and merge rules stay the same. Pass the strategy to
`createCss` (and the same instance to the extractor):

```ts
import { createCss } from "yumcss/css";
import { createNamedAtomsStrategy } from "yumcss/css/named";

export const css = createCss(preset, { className: createNamedAtomsStrategy("ui") });
```

| Import              | Factory                                                                    | Output example                              | CSS owned by |
| ------------------- | -------------------------------------------------------------------------- | ------------------------------------------- | ------------ |
| _(default)_         | none                                                                       | `1f29p40`                                   | YumCSS       |
| `yumcss/css/named`  | `createNamedAtomsStrategy(prefix = "pw")`                                  | `pw-color-$blue-500`, `pw-_hover-color-red` | YumCSS       |
| `yumcss/css/stylex` | `createStyleXAdapter({ classNamePrefix, debug })`                          | `x1a2b3c`                                   | YumCSS       |
| `yumcss/css/panda`  | `createPandaAdapter({ propClasses, prefix, conditions })`                  | `bg-c_red.500`, `hover:bg-c_red.500`        | Panda        |
| `yumcss/css/unocss` | `createUnoCssAdapter({ conditions, preset })`                              | `[color:red]`                               | UnoCSS       |
| `yumcss/tw`         | `createTwAdapter({ variants, bridge, preset })` (generated as `twAdapter`) | `bg-blue-500`, `hover:text-blue-400`        | Tailwind     |

"CSS owned by YumCSS" strategies keep using YumCSS's stylesheet, so `cx()`
merging works the same. The others hand CSS generation to another engine,
and the extractor serves an empty `yumcss:css`. See
[Tailwind classes from css()](/tailwind/tailwind-classes/).

[Try every strategy](/tools/playground/) with the playground's adapter switch.

Panda property names come from the resolved project's generated class metadata.
For the pinned Panda 1.12.1 stock configuration, `backgroundColor` uses `bg-c`,
`color` uses `c`, and `borderRadius` uses `bdr`. Without `propClasses`, the
adapter falls back to hyphenated property names. It supports non-hashed names
with Panda's default `_` separator; custom separators and hash mode are unsupported.
Pass Panda's own token spellings when consuming its generated stylesheet.

The playground executes the selected engine in the browser: Panda's generated
`css()` runtime and official generator, Tailwind's compiler, UnoCSS's generator,
or StyleX's Babel compiler and `stylex.props`. Atomic and named atoms use the
YumCSS runtime sheet. Its isolated preview document receives the actual emitted
CSS, including native layers, resets, variables and conditions. Compiler errors
replace the preview; unsupported semantics are not simulated with inline styles.

The example preset is explicit playground configuration. Panda's configuration
and runtime artifacts are generated from the official resolved presets plus
the example's property bindings and conditions. Tailwind uses the generated
example theme; UnoCSS uses `preset-wind3`; StyleX compiles resolved example values.
The playground's native StyleX engine is separate from the library's lightweight
sheet-backed `createStyleXAdapter` strategy described above.

## Writing your own

```ts
import type { ClassNameStrategy } from "yumcss/css";

export const prefixed: ClassNameStrategy = {
	name: "acme",
	sheetBacked: true,
	toClassName: (key, value) => `acme-${key}-${value}`.replace(/[^\w-]/g, "_"),
};
```

- `key` is the flattened path, including conditions (`_hover__color`), and
  `value` is the normalized value.
- Return `null` to fall back to the default hash. A name with whitespace is
  ignored, and the hash is used.
- Throw to **refuse** a declaration the target can't express.
- `sheetBacked: true` means YumCSS still writes the CSS for your class names.
  Leave it unset when another engine compiles them.
- `css.vars()` classes aren't affected by strategies.
