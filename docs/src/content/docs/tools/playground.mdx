The playground runs the real YumCSS compiler in your browser. Every scenario
shows the same component written with `tw()`, `css()`, and `dss()`, a live
preview you can interact with, and everything YumCSS produced along the way.

</LinkButton>

## What you see

| Panel                                     | Shows                                                                      |
| ----------------------------------------- | -------------------------------------------------------------------------- |
| **Live preview**                          | The rendered component, with controls for its props and theme              |
| **Class string**                          | The exact `className` the call returns                                     |
| **Generated CSS**                         | The atomic rules and token variables written for this file                 |
| **css() atoms / Declarations to classes** | Which declaration produced which class                                     |
| **Tokens**                                | Tokens kept or pruned for this example                                     |
| **Build-time fold**                       | Whether the call was folded to a string at build time, or stays at runtime |
| **StyleProgram IR**                       | The semantic program the compiler and migrations share                     |
| **Execution evidence**                    | What actually ran in the sandbox                                           |

Use the **API** switch to compare `tw()`, `css()`, and `dss()`, and the
**adapter** switch to see the same `css()` call produce atomic, named,
Tailwind, UnoCSS, Panda, or StyleX class names.

## Sharing

The URL holds the scenario, the API, and the class-name adapter
(`/basics?api=css&adapter=tailwind`). When you run edited code (<kbd>⌘</kbd>

<kbd>↵</kbd>), the first file is encoded in the URL hash, so copying the address bar shares your
exact example.

## Migration lab

The **migration examples** page (`/migrate`) runs the real migration adapters
on the documented examples of each library: pick a source (styled-components,
Emotion, Panda, StyleX, …) and a target, then read the output, the capability
decision, and the residual report.
